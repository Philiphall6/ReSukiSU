# TCL T653T01 V643 volatile port

This branch contains the Android TV and diagnostics layer for the TCL C855
laboratory target:

- firmware display ID containing `T653T01` and `V643`;
- Android 14 / API 34;
- kernel release `5.15.180-android14-11`;
- 32-bit Android manager (`armeabi-v7a`) on an arm64 kernel.

## Safety boundary

The exact target is treated as **volatile only**. Manager paths that can patch,
restore, uninstall from, or otherwise write a boot partition are rejected with
`EPERM`. AnyKernel flashing is rejected as well. This port does not unlock the
bootloader, patch `boot.img`/`vbmeta`, or make the root state persistent.

The target match is intentionally exact. A nearby TCL version is not assumed to
be compatible.

GhostLock is not part of this repository or release. It is an external,
volatile loader used only by the device laboratory. This fork starts at the
ReSukiSU LKM boundary: the loader must hand it a coherent kernel/SELinux state.

## Android TV changes

The manager advertises Leanback support, does not require a touchscreen, and
exposes a Leanback launcher entry so it can be operated with a TV remote.

The Superuser list and application profile are D-pad aware. Opening an
application profile places focus on the Superuser switch, and the remote's
center/enter key grants or revokes access without requiring a pointer or touch
screen.

T653T01 uses a 32-bit Android application process on an arm64 kernel.  The
module therefore chains the existing `task_fix_setuid` LSM handler for AArch32
compatibility tasks so the signed manager receives the ReSukiSU driver file
descriptor.  Native arm64 tasks keep the upstream tracepoint route.

## Root-grant diagnostics

`ksud debug root-diagnose` performs a bounded diagnostic in a child process. It
reports:

- manager and late-load flags returned by the driver;
- process architecture;
- UID/EUID before the grant request;
- the `KSU_IOCTL_GRANT_ROOT` result and its error;
- UID/EUID after a successful ioctl.

The manager displays that diagnostic when the LKM responds but a root shell
cannot be obtained. The manager process itself is never converted to UID 0 by
this diagnostic.

## Build validation

Validated locally on Linux Mint with:

```text
./gradlew :app:assembleRelease
cargo +nightly ndk b -P 26 -t armv7-linux-androideabi -r
cargo +nightly ndk b -P 26 -t aarch64-linux-android -r
```

The APK must then be repacked with the matching `ksud` binaries. A locally
signed APK is not automatically a trusted KernelSU manager: its certificate
must match the kernel module's manager identity before an on-device test.

## Dedicated v1.0 identity

The TCL build is intentionally separate from the official manager:

- package: `com.philiphall6.resukisu.tcl`;
- certificate DER size: `860` bytes;
- certificate SHA-256:
  `d3058af8ca0fa6e486ff10362ef941fbf96cf7f593548f048a338e6a63ea5ea1`;
- module package restriction: `KSU_MANAGER_PACKAGE` is set to the package above.

The private keystore remains on the Mint build host and must never be committed
or attached to a release. The public size/hash pair is compiled into the LKM.

Reproducible candidate builds use:

```text
scripts/build-tcl-v643-manager.sh
scripts/build-tcl-v643-lkm.sh
```

## Validated v1.0 scope

The dedicated manager/LKM pair has been validated on the laboratory TCL C855
running the exact V643 target described above:

- the signed manager is recognized by the late-loaded module;
- the 32-bit manager can communicate with the arm64 LKM;
- an ordinary 32-bit Android application can be granted and denied `su`;
- the grant switch is operable with the TV remote;
- a granted process reaches `uid=0`, with SELinux remaining enforcing;
- Verified Boot remained green, vbmeta remained locked and verity remained
  enforcing during the volatile test.

This is not a general T653T01 module. It must not be loaded on another firmware,
kernel release, model or architecture merely because the names look similar.
Only V643 with kernel release `5.15.180-android14-11` has been validated.

The v1.0 release is not a self-contained root exploit and does not provide
persistent root. It contains the ReSukiSU manager and the exact V643 LKM. An
already-authorized, compatible volatile loader is required to place the LKM in
the running kernel. Rebooting the TV removes the volatile root state.

Do not use the manager's generic kernel installation/update action on this TV.
Persistent boot-image installation, boot/vbmeta modification, OEM unlocking
and firmware flashing are outside this port's scope and are intentionally not
supported.
